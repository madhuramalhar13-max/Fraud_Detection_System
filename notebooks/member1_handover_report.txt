6. RECOMMENDED INPUT FEATURES & PREPROCESSING PIPELINE
--------------------------------------------------------------------------------
A. Numerical Features (Scale via StandardScaler or RobustScaler):
   1. 'Transaction_Amount'          : Monetary value (Apply RobustScaler / log1p)
   2. 'Account_Balance'             : User balance (Apply StandardScaler)
   3. 'Daily_Transaction_Count'     : Daily velocity metric (Apply StandardScaler)
   4. 'Card_Age'                    : Account age in months (Apply StandardScaler)

B. Binary Behavioral Feature (Pass directly, no scaling):
   5. 'Previous_Fraudulent_Activity': Historical fraud flag (0 or 1)

C. Categorical Features (Apply OneHotEncoder(drop='first', handle_unknown='ignore')):
   6. 'Transaction_Type'            : 4 categories ('POS', 'Bank Transfer', 'Online', 'ATM Withdrawal')
   7. 'Device_Type'                 : 3 categories ('Laptop', 'Mobile', 'Tablet')
   8. 'Location'                    : 5 cities ('Sydney', 'New York', 'Mumbai', 'Tokyo', 'London')
   9. 'Merchant_Category'           : 5 industries ('Travel', 'Clothing', 'Restaurants', 'Electronics', 'Groceries')
   10. 'Card_Type'                  : 4 card brands ('Amex', 'Mastercard', 'Visa', 'Discover')

D. Engineered Feature Recommendations:
   - 'Amount_to_Balance_Ratio' = Transaction_Amount / (Account_Balance + 1.0)
   - Temporal Features from 'Date':
       * Month = Date.month (1 to 12)
       * Day_Of_Week = Date.dayofweek (0 to 6)
       * Is_Weekend = Date.dayofweek.isin([5, 6]).astype(int)


7. COLUMNS TO EXCLUDE & DATA LEAKAGE RULES
--------------------------------------------------------------------------------
1. 'Transaction_ID':
   - EXCLUDE from feature matrix X. It is a 100% unique primary key. Passing it causes
     artificial memorization / severe overfitting. Retain as index / audit key.
2. 'Fraud_Label':
   - EXCLUDE from feature matrix X. Isolate strictly as target vector y.
3. 'Date' (Raw String):
   - EXCLUDE raw string. Extract numerical/cyclical temporal features and use Date
     for chronological train-test splitting.
4. 'User_ID':
   - EXCLUDE from raw one-hot encoding (8,963 unique users creates dimensionality explosion).
     Only use for out-of-fold historical aggregates if engineered strictly within CV folds.

LEAKAGE PREVENTION RULES:
  * Never fit scalers or encoders on the whole dataset. Fit on X_train only, then transform X_val/X_test.
  * Encapsulate preprocessing inside a scikit-learn Pipeline or ColumnTransformer.
  * For k-fold cross validation, fit preprocessing strictly within each training fold.


8. MODEL EVALUATION METRICS GUIDANCE FOR MEMBER 2
--------------------------------------------------------------------------------
* Avoid relying on standard Accuracy: A naive model predicting all 0s achieves 67.87%
  accuracy but catches 0% of fraud ($1.6M+ in losses).
* Primary Benchmark Metrics:
    1. Recall (Sensitivity) : Maximize detection of fraudulent events.
    2. Precision            : Minimize false alarms and customer friction.
    3. F1-Score             : Harmonic balance between Precision and Recall.
    4. PR-AUC (Precision-Recall AUC): Primary metric for model selection.
    5. ROC-AUC              : Secondary ranking performance metric.
* Recommended Model Algorithms:
    - Baseline: Logistic Regression (with scaled numericals and one-hot categoricals).
    - Primary Ensembles: Random Forest, LightGBM / XGBoost, HistGradientBoostingClassifier.

10. LIMITATIONS & UNRESOLVED DATA QUALITY ISSUES
--------------------------------------------------------------------------------
1. Synthetic Uniformity:
   Marginal fraud rates are uniform across categories (~32%), and bivariate Pearson
   correlations with Fraud_Label are near zero (max |-0.0071|). High model performance
   will require non-linear ensemble models and composite interaction features.
2. Temporal Resolution:
   Timestamps are at daily granularity (YYYY-MM-DD). Sub-hourly velocity (e.g. 3 charges
   in 5 minutes) cannot be extracted; velocity is captured via 'Daily_Transaction_Count'.
3. Zero-Dollar Authorizations:
   Two $0.00 transactions exist (both fraud). They are preserved intentionally as valid
   card-testing attack signatures.
